# handoff_260305_2.md — simdoc v0.3 PDF Rendering Improvements

> Scope: Improve PDF output quality by integrating the Eisvogel Pandoc LaTeX template and shipping it directly with the simdoc package.

This handoff extends the PDF export feature introduced in `handoff_260305_1.md`.

Goals:

- Produce visually pleasant PDFs by default
- Avoid requiring users to manually install templates
- Keep simdoc deterministic and simple
- Provide clear attribution to the Eisvogel template

---

# Specs

## S-260305-2-1 — Bundled PDF template

The simdoc package must ship with the **Eisvogel Pandoc LaTeX template**.

Template repository:

https://github.com/Wandmalfarbe/pandoc-latex-template

The template file (`eisvogel.latex`) is stored inside the simdoc package.

Example package layout:

```
simdoc/

src/
  simdoc/
    templates/
      eisvogel.latex
```

The template is treated as a static asset.

---

## S-260305-2-2 — No manual installation required

Users must **not** be required to manually install the template into Pandoc directories.

The template must be referenced directly via its filesystem path when invoking Pandoc.

Example command generated internally:

```
pandoc temp.md -o output.pdf --template /path/to/eisvogel.latex --pdf-engine=xelatex
```

This ensures deterministic behavior across environments.

---

## S-260305-2-3 — New PDF preset

A new preset named `"eisvogel"` is introduced.

Example usage:

```
doc.save_pdf("report.pdf", preset="eisvogel")
```

Preset expands to:

```
--template=<internal_template_path>
--pdf-engine=xelatex
```

No additional arguments are required.

---

## S-260305-2-4 — Default preset change

The `default` PDF preset should now use the Eisvogel template.

Mapping becomes:

```
default → eisvogel
```

Rationale:

The Pandoc default LaTeX template produces poor visual output.

Eisvogel provides significantly better formatting out-of-the-box.

---

## S-260305-2-5 — Template path resolution

The template path must be resolved dynamically from the installed package.

Implementation must use `importlib.resources`.

Example:

```python
from importlib import resources

template_path = resources.files("simdoc.templates") / "eisvogel.latex"
```

The resolved path is passed to Pandoc.

This guarantees compatibility with:

- installed wheels
- editable installs
- packaged distributions

---

## S-260305-2-6 — Pandoc invocation behavior

The pandoc command becomes:

```
pandoc
  temp.md
  -o output.pdf
  --template=<resolved_template_path>
  --pdf-engine=xelatex
```

User supplied `pandoc_args` remain appended after preset arguments.

File content copied from the upstream repository.

## I-260305-2-2 — Update project packaging

Ensure template file is included in the wheel.

Update `pyproject.toml` if necessary to include package data.

Example:

```
[tool.hatch.build.targets.wheel]
packages = ["src/simdoc"]
include = ["src/simdoc/templates/*.latex"]
```

---

## I-260305-2-3 — Resolve template path

Add helper function inside `doc.py` or a small internal helper module.

Example:

```python
from importlib import resources


def _get_eisvogel_template() -> str:
    path = resources.files("simdoc.templates") / "eisvogel.latex"
    return str(path)
```

---

## I-260305-2-4 — Update preset resolver

Extend `_resolve_preset_args()`.

Example:

```python
presets = {
    "default": [
        "--template", _get_eisvogel_template(),
        "--pdf-engine=xelatex"
    ],

    "eisvogel": [
        "--template", _get_eisvogel_template(),
        "--pdf-engine=xelatex"
    ],

    "article": [
        "--pdf-engine=xelatex"
    ]
}
```

Note:

The template path must be resolved **at runtime**, not at module import time.

---

## I-260305-2-5 — Update save_pdf()

The preset arguments must be inserted **before user-supplied arguments**.

Final argument order:

```
pandoc
input.md
-o
output.pdf
<preset args>
<user pandoc_args>
```
