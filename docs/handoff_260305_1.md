# Specs

## Table of Contents

### S-260305-1-1 — Explicit TOC block

A Table of Contents is created via an explicit builder method:

```python
doc.toc()
```

- `doc.toc()` appends a `TocBlock` to the document.
- The TOC is rendered exactly where the block appears.
- `to_markdown()` does **not** implicitly generate a TOC.

Rationale:

The document remains an **append-only list of blocks**.

---

### S-260305-1-2 — Default heading levels

Default levels included in the TOC:

```
(2, 4)
```

Equivalent calls:

```python
doc.toc()
```

```python
doc.toc(levels=(2,4))
```

User override allowed:

```python
doc.toc(levels=(1,6))
```

Validation:

```
1 ≤ min ≤ max ≤ 6
```

Invalid ranges raise `SimDocError`.

---

### S-260305-1-3 — GitHub-style slug generation

TOC anchors follow **GitHub-style heading slugs**.

Algorithm:

1. lowercase
2. spaces → hyphens
3. remove punctuation
4. collapse repeated hyphens
5. ensure uniqueness using suffixes

Example:

```
## Data Analysis
## Data Analysis
```

Produces:

```
#data-analysis
#data-analysis-1
```

This behavior must be deterministic.

---

### S-260305-1-4 — Two-pass rendering

Markdown rendering uses **two passes**.

Pass 1:

- scan headings
- generate slugs
- resolve duplicates

Pass 2:

- render blocks
- render TOC blocks using the heading index

Rationale:

- simpler implementation
- deterministic output
- TOC may appear anywhere in the document

---

### S-260305-1-5 — TocBlock structure

Internal block definition:

```python
@dataclass(frozen=True)
class TocBlock:
    title: str | None
    levels: tuple[int, int]
```

Builder API:

```python
doc.toc(
    title="Contents",
    levels=(2,4)
)
```

Defaults:

```
title = "Contents"
levels = (2,4)
```

If `title` is `None`, the heading is not rendered.

Example output:

```markdown
## Contents

- [Intro](#intro)
- [Methods](#methods)
```

# PDF Export

### S-260305-2-1 — Pandoc backend

PDF export uses **Pandoc**.

Pipeline:

```
Doc → Markdown → pandoc → PDF
```

Pandoc must be available on the system PATH.

---

### S-260305-2-2 — PDF support in core package

PDF export is included in the core `simdoc` package.

No optional extra is required.

The only external requirement is the `pandoc` executable.

---

### S-260305-2-3 — Temporary Markdown workflow

PDF generation uses a temporary Markdown file.

Process:

```
Doc
 → to_markdown()
 → temporary .md file
 → pandoc temp.md -o output.pdf
```

Rationale:

- easier debugging
- simpler subprocess handling

---

### S-260305-2-4 — Pandoc missing behavior

If the `pandoc` executable is not found:

```
SimDocError
```

Example message:

```
pandoc executable not found.
Install pandoc: https://pandoc.org/installing.html
```

Detection via:

```
shutil.which("pandoc")
```

---

### S-260305-2-5 — Pandoc argument passthrough

`save_pdf()` supports optional Pandoc arguments.

API:

```python
doc.save_pdf(
    "report.pdf",
    preset="default",
    pandoc_args=None
)
```

User override example:

```python
doc.save_pdf(
    "report.pdf",
    pandoc_args=["--pdf-engine=xelatex"]
)
```

Arguments are appended to the pandoc command.

---

### S-260305-2-6 — Presets

Simdoc provides **named presets**.

Example:

```python
doc.save_pdf("report.pdf", preset="default")
doc.save_pdf("report.pdf", preset="article")
```

Presets expand to predefined pandoc arguments.

Example mapping:

```
default → []
article → ["--pdf-engine=xelatex"]
```

User `pandoc_args` are appended after preset arguments.

## I-260305-5 — PDF export method

Add to `Doc`:

```python
def save_pdf(
    self,
    path: str | PathLike[str],
    *,
    preset: str | None = "default",
    pandoc_args: list[str] | None = None
) -> Path
```

Implementation steps:

1. call `to_markdown()`
2. write temp `.md`
3. resolve preset args
4. run pandoc via `subprocess.run`
5. return output `Path`
